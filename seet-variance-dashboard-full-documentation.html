1 · Overview & Purpose

The SEET Variance Dashboard (myMVP — Monitor, Validate and Pinpoint) is a private, single-page web application built for the ODC SEET team. It has one mission:

  • Variance Monitoring — lets each team member sign in, view their own private ILC vs billable-hour variance records imported by an admin, flag discrepancies as updated, and submit an explanation to the audit team for review.
The app is deployed as a static single HTML file hosted on Firebase Hosting. All dynamic data is persisted in Firebase Firestore. No server-side rendering is required.

2 · Tech Stack

Firebase Firestore
Primary cloud database — stores all user profiles, variance records, and review submissions.
Firebase Auth
Email/password authentication. Three roles: admin, audit, and user. Password-change enforcement on first login.
Firebase Hosting
Static file host serving index.html and 404.html.
Vanilla JavaScript
No framework. Firebase compat SDK v10.12.2 loaded from Google CDN. Google Fonts (Inter + Space Grotesk) via @import.

Authentication lifecycle

Firebase Auth fires onAuthStateChanged on page load. The handler handleAuthState() reads the user's Firestore profile (users/{uid}), sets the role, conditionally shows admin/audit UI, and calls loadMyVariances().

Navigation

The app uses a CSS-class–based router. Every "page" is a <div class="page"> in the DOM. The navigate() function removes active from the current page and adds it to the target. Only two pages exist: My Variances and Pending Audit Review.

4 · User Roles & Permissions

RoleHow AssignedWhat They Can Do
Admin Hard-coded UIDs in INITIAL_ADMIN_PROFILES or set by another admin in Firestore. Import variances for any user, manage Firestore user profiles, read all variance records, see Import button.
Audit Admin sets role: "audit" in the user's Firestore profile. View Pending Audit Review nav item. Read all users' varianceReviews. Approve or Reject submissions.
User Admin creates the account and assigns a talentId. View their own variance records only. Toggle "Updated" and submit an explanation for audit review.
Unauthenticated Anyone who opens the URL before signing in. Sees the My Variances page with a "Sign in required" prompt. No data is accessible.
The Configure button uses a separate quarterly passcode (format: Q[1–4][YEAR], e.g. Q32026) — it only grants access to update the Monday Board ID stored in localStorage, not Firebase auth elevation.

5 · Pages & Capabilities

My Variances User Admin
The primary page. Displays the signed-in user's ILC vs billable-hour variance records in a horizontally-scrollable table. Columns: Group, Date, Day, Work Item ID, ILC Hours, Billable Hrs, Monday Status, Expected Status, Issue Type, Issue Detail, Updated. Numeric hour cells are highlighted green (match) or red (mismatch). Users can tick the "Updated" toggle on any row to trigger the review submission flow. Admins see an "Import variances" button.
Pending Audit Review Audit only
Shows all variance review submissions across all users, each displayed as a card with the submitter's name, email, Talent ID, submission date, explanation, and status (Pending / Completed / Rejected). Auditors can Approve (one click) or Reject (opens compose modal → pre-fills a rejection email via mailto:). A badge counter on the nav item shows pending count.

6 · Key User Flows

A — Sign In

1
Click Sign in in the sidebar.
2
Enter the email and temporary password provided by the admin.
3
Click Sign in. On success the modal closes automatically and your variance records load.
4
If mustChangePassword: true is set on your profile: the modal re-opens in "Update your password" mode. Enter a new password (min 6 chars) and click Update password. Variances load after this is complete.

B — Submit a Variance Review (User)

1
On My Variances, locate the row where ILC and billable hours differ.
2
Tick the Updated toggle on that row.
3
A confirmation dialog appears. Click Confirm to proceed or Cancel to revert.
4
Type your explanation in the compose window and click Send.
5
The review is saved to Firestore with status: "pending". Your default email client opens pre-addressed to all auditor-role users.
6
Send the email. The Audit Team will see the submission in Pending Audit Review.

C — Audit a Variance Review (Auditor)

1
Sign in with your audit-role account. The Pending Audit Review nav item appears with a badge count.
2
Click Pending Audit Review to load all submissions.
3
Click Approve to mark it completed, or Reject to open the rejection compose window.
4
When rejecting: enter the reason and click Send Reject Email. Firestore updates to rejected and your email client opens a pre-filled email to the submitter.

D — Import Variance Records (Admin)

1
Sign in as admin. The Import variances button appears in the My Variances page header.
2
Click it — the Import Guide modal opens with step-by-step instructions (run npm run import:variances from the project folder using a local script that holds credentials).
3
Variance records are written to users/{uid}/variances/{varianceId} in Firestore. Only admins have write access.

7 · Admin Operations

Configure the Monday Board ID

Click Configure in the sidebar, enter the quarterly passcode (Q[1-4][YEAR]), and when prompted enter the numeric Monday Board ID. This is stored in localStorage on the admin's browser (used by any admin-side import scripts).

The quarterly passcode rotates every quarter. Q1 = Jan–Mar, Q2 = Apr–Jun, Q3 = Jul–Sep, Q4 = Oct–Dec. Example for Q3 2026: Q32026.

Creating User Accounts

  1. Create the Firebase Auth account via Firebase Console.
  2. Create the Firestore document users/{uid} with fields: talentId, role (user / audit / admin), email, mustChangePassword: true.
  3. Share the temporary password. The user is forced to set a new password on first login.

9 · Security Rules

Firestore rules enforce:

  • users collection — a user can only read their own profile. Admins and auditors can read all profiles (needed to build the review email recipient list).
  • User profiles — only admins can create or delete. A user can only update their own mustChangePassword flag (to clear it after setting a new password).
  • Variances sub-collection — readable by owner, admin, and auditor. Writable only by admin.
  • VarianceReviews sub-collection — owner can create and update their own. Auditors and admins can read all and update status. Only admins can delete.
Hard-coded admin UIDs (zdhAsiaIXpQwEJ0v1YmH26hK6xL2, TDg3rvs7ZfQTggdBUx4xEGNL1P42) are embedded in both firestore.rules and the INITIAL_ADMIN_PROFILES constant in index.html. If these UIDs change, both files must be updated and rules re-deployed.

10 · How To Do It Correctly

Adding a new user

  1. Create the account in Firebase Console → Authentication → Add user.
  2. Note the generated UID.
  3. In Firestore → users → Add document, set the document ID to that UID and add: talentId, role: "user", email, mustChangePassword: true.
  4. Share the email and temporary password with the new user.

Setting a user's role to auditor

  1. In Firestore, open users/{uid}.
  2. Change the role field to "audit".
  3. The user will see the Pending Audit Review nav item on their next sign-in.

Deploying a Firestore rules update

  1. Edit firestore.rules.
  2. Run firebase deploy --only firestore:rules from the project root.

What the quarterly passcode is

The Configure passcode is generated client-side as Q + quarter number + 4-digit year. Examples: Q12026 (Jan–Mar 2026), Q32026 (Jul–Sep 2026).

Resetting a user's password

  1. In Firebase Console → Authentication, use "Send password reset email" or set a new temporary password.
  2. In Firestore, set mustChangePassword: true on the user's profile so they are forced to choose a new one on next login.

Importing variance records

Variance records are never entered through the dashboard UI directly. They are imported via a local admin script (npm run import:variances) that holds the Firebase service-account credentials. The Import Guide modal on the dashboard provides the exact steps.
